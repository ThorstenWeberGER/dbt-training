This dbt curriculum starts with a broken model. That's the point.

Most dbt tutorials teach you to build. Almost none teach you to debug — the code you're handed already works, so there's nothing to figure out.

Building follows a recipe. Debugging means reading a DAG you didn't write and being wrong once or twice before you're right. That's most of what running dbt in production actually looks like.

So I built the exercises around that part on purpose: **3 real bugs**, already sitting in the code, that you have to find and fix yourself.

What's behind it:
🟢 **12 modules** across 2 tiers — full lesson plans, Slidev decks, graded exercises
🟡 A real dbt project: **15 models**, 3 macros, 1 SCD2 snapshot — runs on DuckDB, **zero Snowflake credentials** needed
🔴 A 3rd tier (advanced testing, incremental patterns, governance) scoped and next

Ramping onto dbt? Inherited a project and need the mental model behind `ref()` and materializations, not just the syntax? This is for you.
