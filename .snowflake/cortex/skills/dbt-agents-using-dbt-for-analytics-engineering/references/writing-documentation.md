# Writing dbt Documentation

Document the reasoning behind data structures, not just their names. Focus on the "why" — business logic, edge cases, and historical decisions that shape the data.

## Table-Level Documentation

Explain grain, purpose, and any special considerations.

**Ineffective:**
```yaml
description: "Table containing customer data"
```

**Effective:**
```yaml
description: >
  Pre-filtered customer table for easier analytics. One row per customer
  whose contract_expiry_date is null or in the future. Excludes churned
  customers — use dim_customers_all for full history.
```

## Column-Level Documentation

For calculated or transformed fields, document what transformation was applied and why.

**Ineffective:**
```yaml
- name: customer_id
  description: "The customer ID"
```

**Effective:**
```yaml
- name: customer_id
  description: >
    Unique customer identifier. Users created before 2020-02-16 have a
    'v1_' prefix due to the platform migration — strip this before joining
    to source systems.
```

## What to Always Document

- Grain definition (one row per X)
- Filters applied (what is excluded and why)
- Non-obvious joins or aggregation logic
- Historical quirks in the source data
- Known data quality issues
- Deprecated columns still present for backwards compatibility

## What Not to Document

- Things obvious from the column name (`order_date: "The date of the order"`)
- Implementation details already clear from the SQL
- Redundant restatements of the model name

## YAML Template

```yaml
models:
  - name: fct_orders
    description: >
      One row per order. Excludes test orders (is_test_order = false).
      Amount fields are in EUR, converted at daily closing rate.
    columns:
      - name: order_id
        description: Primary key. Surrogate key generated by dbt_utils.generate_surrogate_key.
      - name: order_amount_eur
        description: >
          Gross order value in EUR. Converted from source currency using
          exchange rates from ref('exchange_rates_daily') at order date.
          Returns null if exchange rate missing for that day.
```
