# Bloomwell Data Warehouse & SQL Conventions

Project-specific naming, schema, and documentation rules for the Bloomwell dbt + Snowflake
medallion architecture. These rules are **mandatory** — no exceptions without team review.

> For general dimensional modeling principles (Kimball, fact table types, SCD patterns),
> use the `dimensional-modeling` skill. This skill covers Bloomwell-specific conventions only.

## Schema Organization

Each layer lives in its own schema. The schema communicates the layer — table names never repeat it.

| Layer | Schema Pattern | Example |
|---|---|---|
| **Bronze** | `BRONZE.{source_system}` | `BRONZE.HUBSPOT`, `BRONZE.SHOPIFY` |
| **Staging** | `STAGING.{purpose}` *(views only)* | `STAGING.HUBSPOT_PREP` |
| **Silver** | `SILVER.{subject_area}` | `SILVER.APPOINTMENTS`, `SILVER.MEDICATIONS` |
| **Gold** | `GOLD.{use_case}` | `GOLD.FINANCE_REPORTING` |
| **Playground** | `TESTING.*` *(views only)* | `TESTING.dev_thorsten` |

## Table Naming

### Prefixes by Layer

| Layer | Prefix | Example |
|---|---|---|
| Bronze | *(none)* | `BRONZE.HUBSPOT.contacts` |
| Staging | `{source}__{entity}` (double underscore) | `hubspot__contacts` |
| Silver — Dimensions | `dim_` | `dim_patient` |
| Silver — Facts | `fct_` | `fct_prescription` |
| Silver — Bridge | `bridge_` | `bridge_patient_diagnosis` |
| Gold — Marts | `mrt_` | `mrt_monthly_prescription_volume` |

### Core Rules

- **Singular names**: `dim_patient` (one row per patient), not `dim_patients`
- **snake_case everywhere**: no camelCase, no PascalCase
- **No SCD type in name**: use `dim_patient`, document SCD strategy in dbt YAML
- **No version numbers**: no `dim_patient_v2` — replace the model
- **Staging materialization**: views or ephemeral only; tables require documented justification

## Column Naming

### Key Columns

| Type | Convention | Example |
|---|---|---|
| Surrogate key (PK/FK) | `{entity}_key` | `patient_key` |
| Business key (from source) | `{entity}_id` | `hubspot_contact_id` |
| Composite business key | `{entity}_{qualifier}_id` | `appointment_external_id` |

`_key` = surrogate integer generated by our pipeline. `_id` = business identifier from source. Never interchangeable.

### Data Type Suffixes

| Type | Suffix | Example |
|---|---|---|
| Timestamp (with time) | `_at` | `created_at` |
| Date (no time) | `_date` | `birth_date` |
| Boolean | `is_` / `has_` prefix | `is_active`, `has_prescription` |
| Monetary (in cents) | `_amount` | `service_amount` |
| Count / quantity | `_count` / `_quantity` | `appointment_count` |
| Percentage / ratio | `_pct` / `_ratio` | `churn_pct` |
| Duration | `_duration_{unit}` | `call_duration_seconds` |
| Free text | `_text` / `_note` | `cancellation_note` |
| CET timestamp *(Gold only)* | `_cet` postfix | `service_date_cet` |

### General Rules

- Full words: `patient_key` not `pat_key`; `prescription_date` not `rx_dt`
- No SQL reserved keywords as column names — prefix: `appointment_date` not `date`
- Boolean columns must answer yes/no: `is_active` → "is active? yes/no"
- Avoid standalone `type` — use `appointment_type`, `service_type`
- Bronze keeps source column names as-is; renaming happens in staging

## Snowflake Constraints

Add `PRIMARY KEY` and `FOREIGN KEY` to all **Silver** and **Gold** tables. Snowflake does not enforce them — they are metadata for ER diagrams and Cortex AI.

**Both the constraint AND the dbt test are required. One without the other is incomplete.**

```sql
-- dbt post-hook
ALTER TABLE {{ this }} ADD PRIMARY KEY (prescription_key);
ALTER TABLE {{ this }} ADD FOREIGN KEY (patient_key)
  REFERENCES {{ ref('dim_patient') }} (patient_key);
```

| Validate | dbt test |
|---|---|
| PK uniqueness | `unique` + `not_null` on `_key` |
| FK validity | `relationships` referencing parent dim |
| Required fields | `not_null` |

## dbt Documentation Requirements

| Layer | Model description | Column descriptions |
|---|---|---|
| Bronze | Optional | Optional |
| Staging | Optional | Optional |
| **Silver** | ✅ Required (include grain statement) | ✅ All columns |
| **Gold** | ✅ Required (include consumer/use case) | ✅ All columns |

CI fails if Silver or Gold models have missing descriptions or undocumented columns.

### Persist docs to Snowflake comments

```yaml
# dbt_project.yml
models:
  bloomwell:
    +persist_docs:
      relation: true
      columns: true
```

### Grain documentation format

```yaml
models:
  - name: fct_prescription
    description: >
      One row per prescription issued. Grain: one prescription event
      per patient per doctor per prescription_date.
```

## Naming Don'ts

| ❌ Don't | ✅ Do instead |
|---|---|
| Prefix with layer name when schema already says it | `contacts` in `BRONZE.HUBSPOT`, not `brz_hubspot_contacts` |
| Use non-universal abbreviations | `appointment` not `appt`, `pharmacy` not `pharm` |
| Encode data types in names | `patient_name` not `patient_name_varchar` |
| Use generic column names | `appointment_status` not `status` |
| Add version numbers | Replace the model, don't add `_v2` |
| Encode SCD type in table name | `dim_patient` not `dim_patient_scd2` |

## Bloomwell-Specific Anti-Patterns

Common mistakes made in the Bloomwell project — with concrete examples.

### Layer name repeated in table name

```sql
-- ❌ WRONG
BRONZE.HUBSPOT.brz_hubspot_contacts    -- "brz" and "hubspot" both redundant
SILVER.APPOINTMENTS.silver_dim_patient -- "silver" in name

-- ✅ CORRECT
BRONZE.HUBSPOT.contacts
SILVER.APPOINTMENTS.dim_patient
```

### SCD type encoded in table name

```sql
-- ❌ WRONG
dim_patient_scd2
dim_pipeline_type2

-- ✅ CORRECT
dim_patient   -- document SCD strategy in dbt YAML description
```

### Non-universal abbreviations

```sql
-- ❌ WRONG
appt_key    -- appointment
rx_date     -- prescription
pharm_key   -- pharmacy

-- ✅ CORRECT
appointment_key
prescription_date
pharmacy_key
```

### Staging models materialized as tables

```yaml
# ❌ WRONG
models:
  - name: hubspot__contacts
    config:
      materialized: table  # never for staging

# ✅ CORRECT
models:
  - name: hubspot__contacts
    config:
      materialized: view   # or ephemeral
```

### Silver/Gold missing grain statement or column descriptions

```yaml
# ❌ WRONG — CI will fail
models:
  - name: fct_prescription
    description: "Prescriptions."  # no grain, incomplete

# ✅ CORRECT
models:
  - name: fct_prescription
    description: >
      Grain: one prescription event per patient per doctor per prescription_date.
    columns:
      - name: prescription_key
        description: "Surrogate key. MD5-hash over patient_id, doctor_id, prescription_date."
        tests: [unique, not_null]
```
